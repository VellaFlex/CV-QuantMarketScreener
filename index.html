How this manual should be used

First read the screen, then the inputs

Most support issues come from a reversed workflow. Users start inside the input list, but the EA makes its live decisions in the dashboard, execution gate and portfolio layers.

Every tab answers a different question

Signal explains the thesis. Execution explains tradability. Risk explains budget fit. Structure explains price context. INST explains portfolio impact.

Use the visual callouts

The speech bubbles and arrows highlight the support-critical zones: opportunity list, selected symbol, blockers, execution state, overlays and manual execution controls.

Annotated dashboard: the main operating view

Signal QualityMeasures whether the setup is structurally complete enough to stay on the active list.
Decision ConfidenceShows directional conviction. High conviction is still not permission if risk or execution gates block the trade.
Execution StateThis is the final practical outcome. When users report missing trades, this is the first block to inspect.

Input architecture: what the major groups control

Groups 01 to 09

Universe, MTF engine, display logic, alerts, chart workflow, execution core, drawdown control and adaptive intelligence. This is the platform base.

Groups 10 to 18

Tester profile, dynamic universe, capital allocation, broker calibration, auto profile, survival engine, volume spike assist, frequency governor and execution quality gate.

Groups 19 to 26

Validation, preview overlays, institutional signal intelligence, decision engine, open/close matrix, news, portfolio risk and pro trader controls.

Professional workflow: stabilize universe and runtime first, then validate signal layers, then enable execution, then refine floating panel and hotkeys.
